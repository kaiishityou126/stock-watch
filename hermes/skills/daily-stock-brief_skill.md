# 每日 A 股观察简报

工作目录即 stock-watch 仓库根目录。数据大部分已由 cron 抓取入库,本 skill 以读为主;
唯一例外是用户点名"今天"且行情未收盘/无数据时,补拉一次行情(见下)。

> **铁律(优先级最高,覆盖本文件其余一切):你的唯一任务是「用 `python -m report.reader` 读数据 → 直接输出回答正文」。除此之外什么都不做——不要验证数据、不要创建/删除任何临时脚本、不要运行 `python -c`、不要跑测试、不要探查表结构、不要比较文件、不要解释过程。唯一的例外:用户点名"今天"且行情未收盘/无数据时,先执行一次「按需补拉」(见下方小节),再重读、再输出。你的最终回复(会被推送给用户的那条)必须就是回答正文本身,输出完立即结束,同一轮里不要再追加任何内容。**回答末尾固定加一行 `(BOT)`,这是本技能输出的标志,用户靠它确认数据走的是本技能,绝不能省略。**

## 唯一读法:`python -m report.reader`

读数据**只允许**这一条命令,不存在任何其他方式(不自己写 SQL、不查表)。

```
python -m report.reader [--date 符号] [--groups 块1,块2,...] [--size 组:N] [--scenario light|heavy]
```

**`--date` 可取值**(把用户的话直接换成符号,不要自己算日期,符号交给命令解析):
- `today`(今天)/ `yesterday`(昨天)/ `N-days-ago`(N 天前)
- `last-mon`..`last-sun`(上周某天,如 `last-tue` = 上周二)
- `this-mon`..`this-sun`(本周某天)
- `YYYYMMDD`(用户给了具体日期)
- **不传 `--date`**:自动取库中最近交易日(定时任务用这个)

**`--groups`**:`index`(大盘) `sentiment`(情绪) `sectors`(板块) `hot_rank`(雪球热榜) `livenews`(7x24快讯) `dragon`(龙虎榜)。缺省全部。

**`--size` / `--scenario`**:`--size sectors:20,hot_rank:20` 覆盖条数;缺省用 `light` 档。定时简报用缺省即可,不要额外加参数。

命令在仓库根目录执行,库路径由 `config.json` 的 `db_path` 决定(默认 `data/app.db`)。若报找不到库,说明当前目录不是仓库根目录或 `db_path` 配置不对:先 `cd` 到仓库根目录重跑一次(这是唯一允许的纠错,不是验证),仍失败再核对 `config.json` 的 `db_path`。

### 读输出(JSON)

- `date`:实际读到的日期,回答里可注明(如"数据截至 20260811")。
- `error`:本次读不了(日期无数据 / 参数写错)。**把 error 内容原样转述给用户即可,不要调试、不要换参数重试。**
- `sectors` 已是四组:`gainers`(领涨) `losers`(领跌) `inflow`(主力净流入) `outflow`(净流出)。
- `xq_hot_rank_today` / `xq_hot_rank_prev`:热榜两日,对比 rank 可指出排名跃升 / 新进榜单的票。
- `is_close_data`:`true` = 该日行情是收盘数据(可当盘后复盘);`false` = 今天行情是盘中快照,或请求了行情腿但今天还没有数据(此时按"按需补拉"处理)。
- `is_today_data`:`false` = 定时/自动触发时库里没有今天数据(回退到了 `date` 所示的旧日期),应按"按需补拉"处理,不要把旧日期数据当成今天的简报。
- `fetched_at_bj`:仅今天盘中拉取时有,北京时 `HH:MM`,回答里用于"数据截至 HH:MM"措辞。
- 某块为空(如龙虎榜当天无数据):回答里写"该块暂无数据",继续生成其余内容,不报错。

## 按需补拉(唯一写操作)

`python -m market snapshot` 会抓实时行情入库。**只允许在满足以下任一条件时执行,且最多执行一次:**

- **用户点名"今天"**(或"今天的X"),且 reader 输出 `is_close_data: false`(今天行情是盘中快照,或请求了行情腿但今天全空),或
- **用户点名"今天"**,且 reader 输出 `error` 提到今天无数据,或
- **定时/自动触发**(不传 `--date`),且 reader 输出 `is_today_data: false`(库里没有今天数据,自动回退到了 `date` 所示的旧日期)。

**命令**(用户问哪块就拉哪块,`--groups` 与读取一致;`<今天>` = 今天的 `YYYYMMDD`):
- 大盘 → `python -m market snapshot --groups index --date <今天>`
- 板块资金流 → `python -m market snapshot --groups sectors --date <今天>`
- 市场情绪 → `python -m market snapshot --groups sentiment --date <今天>`
- 完整简报 → `python -m market snapshot --groups index,sentiment,sectors --date <今天>`
- 龙虎榜**不拉**(盘后才披露,盘中拉了也空);热榜/快讯**不拉**(雪球爬虫盘中已有)。

**流程:** 补拉一次 → 用同一条 reader 命令重读 → 基于最新输出直接生成回答。

**硬规则(违反即任务失败):**
1. **最多补拉一次**。重读后无论结果如何直接生成,绝不循环、不重试、不再次补拉。
2. **只补拉"今天"**。历史日期(昨天/上周二/具体日期)绝不补拉——那天已过完,库里就是收盘数据,拉了也覆盖不了过去,直接读、有则答、无则转述。
3. **重读后按 A股三大指数判定**:若今天 `indexes` 里**没有**上证综指/深证成指/创业板指三条(只有海外指数或为空)→ 今天休市或尚未开盘,告诉用户"今天暂无行情数据(可能休市或尚未开盘)",可顺带给出 `error` 里的"最近有数据日",不生成行情内容。
4. **禁止顺带操作**:补拉后不运行任何其他命令、不验证数据是否入库。

## 流程

### 1. 判断用户要什么(分档细度)

- **完整简报**(定时任务触发;或用户说"日报 / 简报 / 研报")→ 不传 `--groups`(读全部),按下方完整结构生成。
- **单项**(用户点名某类数据,如"昨天的板块资金流"、"今天的大盘")→ 只读对应 `--groups`,只答那一项,不铺开其他内容。
- **一句话**(问"今天涨了没"这种)→ 读最小数据(如 `--groups index,sentiment`),一两句答完。

### 2. 选日期

- 定时任务:不传 `--date`(自动取最近交易日)。重读后若 `is_today_data: false`(今天数据未入库)→ 按"按需补拉"补拉一次再重读;重读后仍无今天数据(休市或补拉失败)→ 如实告诉用户"今天暂无行情数据(可能休市或尚未开盘)",不把旧日期数据当今天简报。
- 用户点名日期:换成 `--date` 符号,如"今天"→ `today`、"昨天"→ `yesterday`、"上周二"→ `last-tue`、"8月15号"→ `20260815`。
- **用户点名"今天"**:先读。若 `is_close_data: false` 或 `error` 提到今天无数据 → 按上方"按需补拉"补拉一次再重读、再生成。
- 用户点名历史日期但当天无数据:命令返回的 `error` 里带"最近有数据日",把这个信息告诉用户,可问是否按最近有数据日生成。**不补拉。**

### 3. 生成回答

#### 完整简报结构(600~800 字)

1. **一句总览** — 当日市场整体基调
2. **大盘** — 各指数涨跌,海外与 A 股不同步需注明
3. **情绪** — 涨跌比、涨跌停、成交额、两融
4. **板块资金流** — 领涨 / 领跌板块,主力资金流向突出的板块
5. **雪球注意力** — 结合热榜两日对比和快讯,指出关注焦点与排名跃升的票;标注"需交叉验证,非买卖建议"
6. **龙虎榜** — 如有数据,列出重点;盘中补拉场景写"待盘后披露"
7. **风险提示** — 一句

**规则(所有回答都遵守):**
- 不搬运原文,只出加工结论
- 不给任何操作建议
- 资金流为按单子大小估算的近似值(非真实机构 / 散户):措辞"主力净流入估算""中小单净流出估算"
- 热榜 / 快讯反映市场注意力(讨论热度),对未来收益预测性弱,需与当日行情 / 资金流交叉印证
- **盘中快照标注**:若今天数据是盘中拉的(`fetched_at_bj` 存在),回答开头加一句"盘中实时快照,数据截至 {fetched_at_bj}(北京时间),收盘数据以盘后简报为准";两融措辞"最近披露(T+1)"。

#### 单项 / 一句话回答

只答用户问的那一项,格式自由,同样遵守上面规则(不给建议、措辞谨慎)。

## 最终回复:硬约束

**最终回复 = 回答正文,写完就结束。** 以下任何一条违反即视为任务失败:

1. **唯一产出就是回答正文**(完整简报 ≤800 字;单项 / 一句话按需)。读数据只允许 `python -m report.reader`;补拉只允许"按需补拉"小节那一条 `python -m market snapshot`,且最多一次。不存在任何"验证 / 检查 / 确认环境"环节。回答末尾必须加 `(BOT)`(见铁律),不省略。
2. **禁止一切验证行为**:不创建 / 删除临时脚本、不写任何 `.py` 文件、不跑 `python -c`、不跑测试套件、不比较文件、不检查表结构、不报 PASS/FAIL。某块数据缺失或 `error` 时,先按"按需补拉"判定是否补拉,其余直接转述,不调试。
3. **最终回复 = 回答本身**,并且它是这条消息的最后一行。输出完,任务即结束,不要在同一轮里再补任何说明或元信息。
4. **不出现工具词**:正文里不要出现 Hermes / cron / skill / report.reader / market snapshot / 命令行 / 投递 / 渠道 等词。
