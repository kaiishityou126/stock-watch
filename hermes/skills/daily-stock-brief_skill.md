# 每日 A 股观察简报

工作目录即 stock-watch 仓库根目录。数据大部分已由 cron 抓取入库,本 skill 以读为主;
唯一例外是用户点名"今天"且行情未收盘/无数据时,补拉一次行情(见下)。

> **铁律(优先级最高,覆盖本文件其余一切):整个流程只有三步——第 1 步执行下方唯一的读数据命令,第 2 步把正文 markdown 普通写进一个文本文件后调 `python -m report.render` 渲成 PDF,第 3 步最终回复 = 恰好两行:第 1 行一句话说明,第 2 行 `MEDIA:<pdf 绝对路径>`(标签独占一行、行首就是 `MEDIA:`)。除此之外什么都不做:不要验证数据、**禁止任何形式的代码执行(`python -c`、`execute_code`、或写并运行任何 `.py` 脚本)**、不要跑测试、不要探查表结构、不要比较文件、不要解释过程、最终回复除那一句话说明 + MEDIA 行外不加任何文字(恰好两行、不许状态汇报)。代码执行需人工审批,cron 无人值守时会卡住任务——正文只需普通写文件就能完成,没有任何理由要用代码执行。唯一的例外:用户点名"今天"且行情未收盘/无数据时,先执行一次「按需补拉」(见下方小节),再重读、再渲、再输出 MEDIA。**
>
> **禁止「预探测」:** 不得用 `python -c` 探 `sys.executable` / `import` / 依赖是否齐全 / Python 版本 / 任何环境信息。`python -m report.reader` 与 `python -m report.render` 均为已验证可执行的命令,直接走流程即可;真出 ImportError,把缺包信息原文转述给用户,任务结束。

## 唯一读法:`python -m report.reader`

读数据**只允许**这一条命令,不存在任何其他方式(不自己写 SQL、不查表)。

```
python -m report.reader [--date 符号] [--groups 块1,块2,...] [--size 组:N] [--scenario light|heavy]
```

**`--date` 可取值**(把用户的话直接换成符号,不要自己算日期,符号交给命令解析):
- `today`(今天)/ `yesterday`(昨天)/ `N-days-ago`(N 天前)
- `last-mon`..`last-sun`(上周某天,如 `last-tue` = 上周二)
- `this-mon`..`this-sun`(本周某天)
- `YYYYMMDD`(用户给了具体日期)
- **不传 `--date`**:自动取库中最近交易日(定时任务用这个)

**`--groups`**:`index`(大盘) `sentiment`(情绪) `sectors`(板块) `hot_rank`(雪球热榜) `livenews`(7x24快讯) `dragon`(龙虎榜)。缺省全部。

**`--size` / `--scenario`**:`--size sectors:20,hot_rank:20` 覆盖条数;缺省用 `light` 档。定时简报用缺省即可,不要额外加参数。

命令在仓库根目录执行,库路径由 `config.json` 的 `db_path` 决定(默认 `data/app.db`)。若报找不到库,说明当前目录不是仓库根目录或 `db_path` 配置不对:先 `cd` 到仓库根目录重跑一次(这是唯一允许的纠错,不是验证),仍失败再核对 `config.json` 的 `db_path`。

### 读输出(JSON)

- `date`:实际读到的日期,回答里可注明(如"数据截至 20260811")。
- `error`:本次读不了(日期无数据 / 参数写错)。**把 error 内容原样转述给用户即可,不要调试、不要换参数重试。**
- `sectors` 已是四组:`gainers`(领涨) `losers`(领跌) `inflow`(主力净流入) `outflow`(净流出)。
- `xq_hot_rank_today` / `xq_hot_rank_prev`:热榜两日,对比 rank 可指出排名跃升 / 新进榜单的票。每行带 `date`(实际归档日期),若与用户所问日期不一致,回答里要如实注明实际日期。
- `xq_livenews`:点名历史日期时只含该自然日的归档快讯;为空就写"该日无快讯归档",不要拿别的时间的内容充当那天。
- `is_close_data`:`true` = 该日行情是收盘数据(可当盘后复盘);`false` = 今天行情是盘中快照,或请求了行情腿但今天还没有数据(此时按"按需补拉"处理)。
- `is_today_data`:`false` = 定时/自动触发时库里没有今天数据(回退到了 `date` 所示的旧日期),应按"按需补拉"处理,不要把旧日期数据当成今天的简报。
- `fetched_at_bj`:今天行情数据的最新拉取时间(北京时 `HH:MM`)。它本身区分不了盘中/收盘——收盘后拉的数据同样有——是否盘中一律以 `is_close_data` 为准。
- 某块为空(如龙虎榜当天无数据):回答里写"该块暂无数据",继续生成其余内容,不报错。

## 按需补拉(唯一写操作)

`python -m market snapshot` 会抓实时行情入库。**只允许在满足以下任一条件时执行,且最多执行一次:**

- **用户点名"今天"**(或"今天的X"),且 reader 输出 `is_close_data: false`(今天行情是盘中快照,或请求了行情腿但今天全空),或
- **用户点名"今天"**,且 reader 输出 `error` 提到今天无数据,或
- **定时/自动触发**(不传 `--date`),且 reader 输出 `is_today_data: false`(库里没有今天数据,自动回退到了 `date` 所示的旧日期)。

**命令**(用户问哪块就拉哪块,`--groups` 与读取一致;`<今天>` = 今天的 `YYYYMMDD`):
- 大盘 → `python -m market snapshot --groups index --date <今天>`
- 板块资金流 → `python -m market snapshot --groups sectors --date <今天>`
- 市场情绪 → `python -m market snapshot --groups sentiment --date <今天>`
- 完整简报 → `python -m market snapshot --groups index,sentiment,sectors --date <今天>`
- 龙虎榜**不拉**(盘后才披露,盘中拉了也空);热榜/快讯**不拉**(雪球爬虫盘中已有)。

**流程:** 补拉一次 → 用同一条 reader 命令重读 → 基于最新输出直接生成回答。

**硬规则(违反即任务失败):**
1. **最多补拉一次**。重读后无论结果如何直接生成,绝不循环、不重试、不再次补拉。
2. **只补拉"今天"**。历史日期(昨天/上周二/具体日期)绝不补拉——那天已过完,库里就是收盘数据,拉了也覆盖不了过去,直接读、有则答、无则转述。
3. **重读后按 A股三大指数判定**:若今天 `indexes` 里**没有**上证综指/深证成指/创业板指三条(只有海外指数或为空)→ 今天休市或尚未开盘,告诉用户"今天暂无行情数据(可能休市或尚未开盘)",可顺带给出 `error` 里的"最近有数据日",不生成行情内容。
4. **禁止顺带操作**:补拉后不运行任何其他命令、不验证数据是否入库。

## 流程

### 0. 快路径:已生成的 PDF 直接发(命中即结束)

**启用条件:用户消息中明确出现「完整简报」类关键词**。命中其一即可:

- "简报" / "日报" / "研报" / "复盘" / "观察" / "每日 A 股"
- "再来一份" / "再发一次" / "昨天那份" / "昨天发的"

**典型命中**:"给我昨日简报" / "今日 A 股复盘" / "8/27 那份日报再发一下"。
**典型不命中**(走下方完整流程回文本,不要发整份 PDF):
"今日大盘" / "今天涨了没" / "昨日板块资金流" / "今日龙虎榜" / "今天热榜" / 任何点名某块数据的查询。

**只适用于用户询问触发的场景**。
**不适用于定时任务**——cron 触发必须走完整流程,以保证数据是最新的。

```bash
ls -t data/reports/<YYYYMMDD>-*.pdf 2>/dev/null | head -1
```

- **`<YYYYMMDD>` 怎么取**:`今日` = 今天的 `YYYYMMDD`;`昨日` = 昨天的 `YYYYMMDD`;具体日期(8/27 / 8月15号)= 换成对应 `YYYYMMDD`。
- **有一个匹配路径** → 直接回复两行:第 1 行 `A 股观察简报已生成，请查收。`,第 2 行 `MEDIA:<那个路径>`(MEDIA 独占第 2 行),**任务结束,不要走 1~3 步**。
- **没有任何匹配** → 进入下方 1~3 步完整流程。
- 多个匹配时取 `ls -t` 第一个(按 mtime 倒序的最新一份),命名冲突场景(盘中手动覆盖)取最新落盘的那份。

**快路径的隐含前提:** PDF 是 `<YYYYMMDD>-<title>.pdf` 格式(同 `report.render` 输出),是上一次 cron 或询问的产物;不要把临时半成品 / 其他模块的 PDF 当成简报用——文件名前缀必须是用户问的那个 `YYYYMMDD`。

### 1. 判断用户要什么(分档细度)

- **完整简报**(定时任务触发;或用户说"日报 / 简报 / 研报")→ 不传 `--groups`(读全部),按下方完整结构生成。
- **单项**(用户点名某类数据,如"昨天的板块资金流"、"今天的大盘")→ 只读对应 `--groups`,只答那一项,不铺开其他内容。
- **一句话**(问"今天涨了没"这种)→ 读最小数据(如 `--groups index,sentiment`),一两句答完。

### 2. 选日期

- 定时任务:不传 `--date`(自动取最近交易日)。重读后若 `is_today_data: false`(今天数据未入库)→ 按"按需补拉"补拉一次再重读;重读后仍无今天数据(休市或补拉失败)→ 如实告诉用户"今天暂无行情数据(可能休市或尚未开盘)",不把旧日期数据当今天简报。
- 用户点名日期:换成 `--date` 符号,如"今天"→ `today`、"昨天"→ `yesterday`、"上周二"→ `last-tue`、"8月15号"→ `20260815`。
- **用户点名"今天"**:先读。若 `is_close_data: false` 或 `error` 提到今天无数据 → 按上方"按需补拉"补拉一次再重读、再生成。
- 用户点名历史日期但当天无数据:命令返回的 `error` 里带"最近有数据日",把这个信息告诉用户,可问是否按最近有数据日生成。**不补拉。**

### 3. 生成回答

#### 完整简报结构(600~800 字)

1. **一句总览** — 当日市场整体基调
2. **大盘** — 各指数涨跌,海外与 A 股不同步需注明
3. **情绪** — 涨跌比、涨跌停、成交额、两融
4. **板块资金流** — 领涨 / 领跌板块,主力资金流向突出的板块
5. **雪球注意力** — 结合热榜两日对比和快讯,指出关注焦点与排名跃升的票;标注"需交叉验证,非买卖建议"
6. **龙虎榜** — 如有数据,列出重点;盘中补拉场景写"待盘后披露"
7. **风险提示** — 一句

**规则(所有回答都遵守):**
- 不搬运原文,只出加工结论
- 不给任何操作建议
- 资金流为按单子大小估算的近似值(非真实机构 / 散户):措辞"主力净流入估算""中小单净流出估算"
- 热榜 / 快讯反映市场注意力(讨论热度),对未来收益预测性弱,需与当日行情 / 资金流交叉印证
- **盘中快照标注**:仅当 `is_close_data: false` 才说明天数据是盘中拉的(此时必有 `fetched_at_bj`),回答开头加一句"盘中实时快照,数据截至 {fetched_at_bj}(北京时间),收盘数据以盘后简报为准";`is_close_data: true` 是收盘数据,**不加**此标注。两融措辞"最近披露(T+1)"。

#### 单项 / 一句话回答

只答用户问的那一项,格式自由,同样遵守上面规则(不给建议、措辞谨慎)。

## 最终回复:硬约束(走 PDF 投递)

**最终回复 = 恰好两行:第 1 行一句话说明,第 2 行 `MEDIA:<pdf 绝对路径>`(标签独占一行),** Hermes cron 会自动把 PDF 作为附件投递到微信(iLink 文件通道,不受 5/min sendmessage 限流)。**违反以下任一条即为任务失败。**

### 三步执行

**第 1 步:读数据**(只允许这一种,见上方「唯一读法」一节)

```
python -m report.reader [--date 符号] [--groups ...]
```

读出来的 JSON 拿在手里,**不要** echo 给用户、不要解释字段含义。

**第 2 步:渲染 PDF**

按上方「3. 生成回答」小节的结构,把正文 markdown 原样写进一个普通文本文件 `brief.md`(普通写文件即可,**不需要任何转义**、不需要拼 JSON),然后执行:

```
python -m report.render --title "<标题>" --content-file brief.md --out data/reports/<YYYYMMDD>-<title>.pdf
```

- **硬规定:正文只能用普通写文件方式写进 `brief.md`,禁止用任何形式的代码执行(`python -c`、`execute_code`、或写并运行任何 `.py` 脚本)来生成这个文件。** 旧契约是 `{title,content}` JSON,需要对正文做 JSON 转义(换行变 `\n`、引号转义等),这一步容易驱使去用 Python 代码来拼转义,而代码执行需人工审批、cron 无人值守时会卡住。现在的 `--content-file` 模式正文是原始 markdown 文本(不经 JSON 解析),普通写文件就能完成,没有理由再用代码执行。
- `--out` 必须给**绝对路径**或仓库根目录下的相对路径(Hermes 的 MEDIA 标签必须能解析到磁盘文件)
- 成功时 `report.render` 在 stdout 输出 `{"ok": true, "path": "..."}`,从 `path` 字段取 PDF 绝对路径
- 失败时 stdout 是 `{"error": "..."}`,把错误原样转述给用户,任务即结束

**第 3 步:最终回复**

你的最终回复必须是**且仅是**两行:第 1 行一句话说明,第 2 行以 `MEDIA:` 开头的标签(独占一行)。无 markdown 围栏、说明只许一句、恰好两行、不许其他前后缀:

```
A 股观察简报已生成，请查收。
MEDIA:C:\Users\MyAi\project\stock-watch\data\reports\20260828-今日A股观察.pdf
```

### 行为约束

1. **三步顺序不可乱**:先 reader → 再 render → 最后 MEDIA。**禁止任何形式的代码执行**(`python -c`、`execute_code`、或写并运行任何 `.py` 脚本)来生成 `brief.md` 或 PDF。
2. **`--title` 参数**:PDF 首页标题与文件名(自动加日期戳)的来源,必填非空字符串。
3. **`brief.md` 正文**:markdown 文本(必填非空)。允许 `#`/`##`/`###` 多级标题、`**加粗**`、`-` 列表、`|` 表格、`> ` 引用、` ``` ` 代码块、段落空行分隔。**不设字符硬限**。`render` 会把 `--content-file` 对应的 markdown 文本原样渲染成 PDF 内容。
4. **路径中的中英文/空格**:`--out` 给的路径里若 title 含中文或特殊字符,会经 `report.render` 自动清洗;LLM 不用手工 URL-encode。
5. **禁止一切验证行为**:不创建 / 删除临时脚本(除了 `brief.md` 这个 renderer 的输入)、不写任何 `.py` 文件、不跑 `python -c` / `execute_code`、不跑测试套件、不比较文件、不检查表结构、不报 PASS/FAIL。某块数据缺失或 `error` 时,先按"按需补拉"判定是否补拉,其余直接转述,不调试。
6. **最终回复 = 恰好两行:第 1 行一句话说明,第 2 行 `MEDIA:` 标签(独占一行、行首就是 `MEDIA:`)**。说明固定为「A 股观察简报已生成，请查收。」(不加「每日/今日/昨日」等日期词,避免与实际交付日期不符),除这句 + MEDIA 行外不补任何说明、元信息、状态汇报、错误堆栈。
7. **不出现工具词**:任何输出(临时 JSON、stdout 解析、最终回复)里**不要**出现 Hermes / cron / skill / report.reader / market snapshot / 命令行 / 投递 / 渠道 / iLink / sendmessage 等词。
8. **业务措辞规则**(原"完整简报结构"的要求全部保留,落到 `brief.md` 正文里):
   - 不搬运原文,只出加工结论
   - 不给任何操作建议
   - 资金流措辞"主力净流入估算""中小单净流出估算"
   - 热榜 / 快讯需注明"反映市场注意力,需与板块资金流与盘面交叉印证,非买卖建议"
   - **盘中快照标注**:仅当 `is_close_data: false` 时,`brief.md` 开头加一句"盘中实时快照,数据截至 {fetched_at_bj}(北京时间),收盘数据以盘后简报为准";`is_close_data: true` 不加。两融措辞"最近披露(T+1)"。
