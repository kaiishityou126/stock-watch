# 每日股票观察简报系统 · 一期设计

- 状态:定稿(2026-07-16)
- 定位:自用 / 研究,非商业化
- 范围:仅一期(最小闭环)。选股、大 V 策略提炼、舆情/政策、板块轮动、情绪反向指标均留后续期。

---

## 1. 目标与边界

### 1.1 一期要做什么
每天自动完成一条最小闭环:

1. **抓取情绪文本源**:微博大 V 博文+评论(已完成)、雪球关注博主/讨论(新建)。
2. **拉当天行情**:盘后拉 A 股板块级涨跌/成交/资金流(近似口径)+ 龙虎榜,存快照。
3. **LLM 出简报**:读当天新增文本 + 当天行情快照,生成一份**每日观察简报**——"今天大 V/散户在聊哪些股和板块,这些板块当天表现如何"。
4. **推送**:经 Hermes 推到飞书。
5. **监控告警**:任一步出错或抓取被风控熔断,推告警给用户。

### 1.2 一期明确不做
- 不做选股、不给买卖信号。
- 不做大 V 投资策略/方法论提炼。
- 不做舆情/突发事件→板块影响、国家政策抓取。
- 不做情绪反向指标、板块轮动判断、宏观趋势预判。

以上留二/三期,每期各走一遍"设计 → 计划 → 实现"。

### 1.3 定性声明(合规与预期)
简报是**观察参考视角**,**不是可下单信号**。LLM 只输出加工后的结论,不搬运原文。

---

## 2. 运行环境与前置假设

- **部署主机**:国内网络下的 Windows 主机(国内云服务器 或 家里 PC,二者对本设计通用)。
- **网络**:国内 → 推送渠道排除 Telegram(墙),用国内可直连渠道。
- **Hermes 已装通**:一期把 Hermes 作为**编排(cron)+ 推送出口**层。实现第一步须先验证 Hermes 可用,否则一期无法起来。
- **诚实风险提示**:云机房 IP 比住宅 IP 更易被微博/雪球风控,换 OS 不解决 IP 问题。对策:用小号、低频 + 随机延时(代码已有)、上线盯日志;频繁 401/403 说明 IP 被盯,再考虑加代理或挪回家里 PC。

## 3. 组件划分(职责单一)

| 组件 | 状态 | 职责 | 依赖 |
|---|---|---|---|
| `weibo-blogger-watch/`(login/crawler/storage/main) | ✅ 已完成 | 微博博文+评论增量抓取 → SQLite | requests、playwright |
| 雪球抓取脚本 | 🆕 新建 | 同微博套路(登录态持久化 / requests / SQLite / 增量),抓关注博主与讨论文本 | requests、playwright |
| `market/` 行情 tool | 🆕 新建 | adata/akshare 薄封装:盘后拉板块涨跌/成交/资金流(近似口径)+ 龙虎榜 → 快照 | adata、akshare |
| `report/` 简报生成 | 🆕 新建 | 读微博+雪球文本 + 行情快照 → 组 prompt → 调 LLM → 简报文本 | 读 SQLite、LLM |
| `notify/` 推送模块 | 🆕 新建 | 简报与告警的**统一出口** → 交给 Hermes → 飞书 | Hermes |
| 监控 / 熔断逻辑 | 🆕 新建 | 各脚本写结构化错误日志 + 连续 401/403 写熔断 flag;Hermes 编排时读 ERROR/flag → 触发告警 | logging、flag 文件 |
| Hermes cron | 编排 | 定时驱动上述全部,**取代 Windows 任务计划** | Hermes |

设计原则:每个组件对外只暴露清晰入口(CLI 或函数),内部实现可独立替换。`notify` 是简报与告警共用的单一推送出口,换渠道只改一处。

## 4. 数据流(每天一轮)

```
[Hermes cron]
  ├─ 早/午/盘中: python main.py crawl --mode incremental        (微博增量)
  │              python xueqiu_crawl.py --mode incremental       (雪球增量)
  │                 → 新文本入 SQLite
  ├─ 盘后(约 15:30 后): 调 market 行情 tool
  │                 → 当天板块涨跌/成交/资金流(近似) + 龙虎榜 → 存快照表
  ├─ 收盘后: report 读(当天新文本 + 当天行情快照)→ 组 prompt → LLM
  │                 → 生成简报文本 → 存 daily_report
  └─ 推送: notify(简报)→ Hermes → 飞书

[贯穿全程]
  任一步出错 → 脚本写 ERROR 日志(结构化,带级别+步骤标签)
  抓取连续 401/403 超阈值 → 写 PAUSED flag,后续抓取跳过
  Hermes 每轮检查 ERROR 行 + flag → 有则 notify(告警)→ Hermes → 飞书
```

## 5. 存储设计

沿用现有单库 `data/app.db`(单文件、好查、好备份;原名 `weibo.db`,因现在多源共用已更名),在其中加表:

- `posts` / `comments` / `crawl_state`(微博,**已有**)。
- **新增** 雪球文本表:结构对齐微博(id 主键去重、增量水位、原文 JSON、纯文本、时间戳)。
- **新增** `market_snapshot`:按日期存板块级——
  - 直接口径:涨跌幅、成交量、成交额;
  - **近似口径(字段名须标注"估算、非真实机构/散户")**:主力净流入(超大+大单)≈机构、中小单净流入≈散户。
- **新增** `dragon_tiger`(龙虎榜):仅上榜股/板块 + 机构专用席位(真机构动向),与资金流分开,作补充信号。
- **新增** `daily_report`:按日期存生成的简报文本(留档、防重复推送、便于回看)。

> 口径说明:A 股无"全板块每日真实机构/散户逐日买卖数据",资金流多为净额、未必拆买卖两额。故用东财按单子大小的净流入做**估算**,并另存龙虎榜作为真机构信号补充。此局限已知并接受。

## 6. 错误处理与监控(核心运维需求)

### 6.1 结构化日志
- 每个脚本用 Python `logging` 写 `logs/<模块>-YYYY-MM-DD.log`。
- 每行带**级别**(INFO/WARNING/ERROR)+ **步骤标签**(抓取/长文/评论/行情/LLM/DB)。
- 该退避重试的重试(抓取层已有);重试用尽或致命错 → `logger.error(...)` 记一条,带上下文(哪个源、哪一步、什么异常)。

### 6.2 熔断
- 抓取脚本内累计"连续 401/403 超阈值" → 写 `PAUSED` flag 文件并停止本轮后续抓取。
- 下次定时任务启动先看 flag:存在则跳过抓取(等用户处理后手动清除),避免撞墙式狂试把账号封死。

### 6.3 告警(与日报共用 notify)
- Hermes 每轮编排结束时,读日志中**级别 = ERROR 的新行** + 检查熔断 flag。
- 有 ERROR 或已熔断 → 调 `notify` 推告警(含哪一步、什么错、是否已熔断)。
- **按级别字段判定,不靠正则抠中文文案** → 改错误提示文案也不失效。

> 设计取舍:监控采用"脚本自报(写日志/flag)+ Hermes 编排时读取推送",而非独立 tail-日志守护进程。后者更脆(日志格式一变即失效、跨进程停抓需额外通信),自用场景前者更稳。

## 7. LLM 与推送

- **LLM**:调用 Hermes 中已配置的模型。一期不纠结选型,能出中文摘要即可。
- **Prompt 要求**:只提"涉及哪些股/板块 + 大 V/散户观点倾向",**不搬运原文**(合规)。
- **推送**:统一走 `notify` → Hermes → 飞书自定义机器人 webhook(渠道由 Hermes 抽象,后续换钉钉/企业微信只改配置)。

---

## 8. 合规红线

- 微博/雪球用户协议禁自动化抓取:仅个人低频自用,勿商业化分发、勿高频、勿公开转发原文;推送只给 LLM 加工后的结论。
- 评论/讨论含他人个人信息,注意保护。建议用小号登录。
- 登录态目录(`.wb_profile/` 等,=账号凭证)与 `data/`(含他人信息)已 gitignore,**绝不提交**。

---

## 9. 一期完成的判定标准

- 微博 + 雪球增量抓取可各自独立跑通,数据正确入库、去重、断点续抓。
- 行情 tool 能拉当天板块行情 + 龙虎榜并存快照(近似字段正确标注)。
- report 能读当天数据、调 LLM、产出一份中文简报并存档。
- notify 能经 Hermes 把简报推到飞书。
- 制造一个错误(如断网/伪造连续 401)能触发日志 ERROR + 熔断 flag,并收到 Hermes 告警推送。
- 以上由 Hermes cron 定时串起,无人值守跑完一整天。
